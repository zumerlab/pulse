In use

Your own source

Pulse is more than Home Assistant. The object does not care where a reading comes from: a car's battery and tires, a boat's tanks and wind, a server's load and disks are systems with channels like any other. Home Assistant happens to be the first source that is real.

What a system is

A system is a title and a few channels. A channel reads the source's state and returns a reading, or nothing when the source has nothing for it. A reading is one of three rings, a big value, one line, the entities it depends on, and optionally an alert with its action. That is the whole contract between a source and the object.

{
  kind: 'p',                  // a band ('p'), switches ('s') or a choice ('c')
  v: 0.74,                    // the band's progress
  dial: { min: 0, max: 100, step: 1, unit: '%', value: 74, set: (v) => command },
  big: '74%', label: '310 km',
  entities: ['battery'],
  alert: { level: 1, big: '12%', why: 'Battery under 15%', verb: 'Find a charger', calls: [command] },
}

Two to four channels that compete for attention, ordered front to back, are a good system. More than that is usually two systems.

What a source is

A source holds the states, tells the object when they change, and takes its commands. In the Home Assistant app it is one interface, PulseSource, implemented twice: over Home Assistant's WebSocket for the app, and over the hass object for the card. A third implementation is the demo homes, which behave without a server.

Where it runs

The core is a plain module that mounts on an element and draws with CSS and a little SVG. It works inside a shadow root, which is what a Home Assistant card is, and on a round screen, which is what a boat's helm or a wall panel may be. The demo app and the Home Assistant app are the two examples in the repository. The steps, from the imports to the theme: In your project.
