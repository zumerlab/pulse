# Pulse

The UI: a radial object with layers by urgency. Uses Orbit (`../orbit`) and Zumly (`../zumly`). Pulse is more than Home Assistant; Home Assistant is the first real source and a thorough demonstration of it.

- Three repos. This one is the core, one npm package at the root: `@zumer/pulse` (`src/`: the object and the board; knows nothing about Home Assistant or machines), with the demo in `demo/` (simulated data on its own early board, served by `npm run dev`; the tests run against it), the site in `docs/`, `scripts/land.mjs` (the globe's coasts). `npm run compile` builds it into `dist/` (tsc for the types, `vite.lib.config.ts` for one ES module, the stylesheet copied), which is what npm ships and what the `exports` point to. The products live beside it: `../pulse-home` (`zumerlab/pulse-home`: Pulse for Home Assistant, the standalone app, the `zumer-pulse` card and strategies and the six demo homes; the first to publish, with a `CLAUDE.md` of its own) and `../pulse-apps` (`zumerlab/pulse-apps`, private: homelab, world, signalk, fleet, prometheus, drones, flights, iss, cameras). Each reads the core live from this checkout when it is beside them (`vite.shared.ts` aliases `@zumer/pulse` to `../pulse/src`, tsconfig `paths` the same; Orbit, Zumly and hls.js deduped onto the product's copies) and the npm package otherwise, so a public clone of a product works alone. A change in the core shows in both at once; a change in the core's dependencies needs `npm install` in each. What is UI of the object goes in the core; what is about a data source goes in its app, in its repo. The products import the core as `@zumer/pulse`, never by relative path.
- The contract (`src/model.ts`): a `PulseHost` hands the board `systems` whose channels `read(ctx)` into a `Reading` (kind, value, big/label, `alert` with a level, `ids` of the things it depends on, optional dial/range/color/image/history/tracks); every thing is an opaque id the host names (`nameOf`, `stateOf`, `changedAt`, `unitOf`), every action an `Action` with the `ids` it touches that the host runs (`act`). The board (`board/`, `mountBoard` in `board/mount.ts`) owns the grid/orbit/layers/list views, the gear (four tabs: content, board, look, tuning), time in the orbit, the system view, the detail and the changes view; a shell passes `strings` for its own words. A detail whose reading has gone, or an object the board no longer has (the last notice, dismissed from its row), closes a step back once Zumly has settled (`zoomOutWhenCurrent` in `board/state.ts`); an object opened from a row stays. A host may add `groups()` (the gear filters by them; a host reads only what is in `ReadContext.groups`), `byGroup()` (the board's second axis: one object per group; past `CROWD` (12) objects the board climbs a level, one object per group of the gear with the chosen systems' channels read within it (`crowd:<group>`, `board/settings.ts`), each member one tap further), `objectOf(id)` (the object of one thing a segment or a row names with `Seg.to`, or a reading with `Reading.to`, whose face then opens it instead of a detail: the board zooms into it from there and reads it while it is open; an aircraft, a quake, a vessel), `statistics(id, days)` (the month of a meter), `language` and `stateText`. A reading's `map` opens a detail with the map big, live and zoomable (`mapDetail`/`turnMap`/`mapControls` in `radial/map.ts`; it keeps the pinch, `data-zooms`); its `link` is a way out to the thing elsewhere, a button in the detail. Hosts swapped at runtime (`setHost`) share system ids.
- Inside `board/`: `context.ts` is the `Board` one mounted board shares (fixed parts, the host and the viewer's choices, readings and actions, caches); every module is functions of it. `types.ts` (public shapes), `settings.ts` (frame, choices, look, ground: flat, a glow, one of three abstract grounds drawn as CSS from the theme's tokens (`artBackdrop`: Aurora, Contours, Grain, chosen on tiles in the gear), or a photo), `state.ts` (readings, order, actions, the code), `draw.ts` (ring with pending/failed, pictures, `setHTML`, which writes only what changed through `radial/morph.ts`: elements stay, so a wave keeps its rhythm and a dot glides; `data-own` marks an element whose content its own code keeps, the live map), `time.ts` (past changes, the month), `dials.ts`, `gear.ts`, `views/` (system, detail, changes, and `board/` with a file per mode: grid, orbit (past twelve it shows eleven and turns a page), layers, list (the center tied to the item it shows by a hand; that item tapped again opens; its measures in the gear's tuning), around `index.ts`), `mount.ts` (makes the `Board`, wires host and Zumly). The stylesheet is `style.css` importing `styles/` (base, object, detail, phone, primitives, board, orbit, layers, gear, compact, list, time, ground) in the order they cascade: a rule moved between parts can change what wins. The lower modules call up through two hooks on the `Board` (`repaint`, `systemView`), never by importing `mount.ts` or a view: no import cycles. A field that changes (`b.host`, `b.local`, `b.ids`, `b.readings`) is read through `b` each time, never kept in a local.
- The core's primitives (`radial/`, a module per family, each primitive next to its gestures; `radial/index.ts` re-exports them): `ring` with `kind` `'p'` (band/dial, with `range` two knobs), `'s'` (switches), `'c'` (a choice, names along the ring); `face` with `image`, which with a `video` (`Picture.video`: a live HLS stream or a file) plays muted over its still through `<pulse-video>` (`radial/video.ts`, an element of its own so a repaint does not restart it: it connects when seen, lets go when not, hls.js where there is Media Source, the browser's own HLS elsewhere, the still when the stream fails); `timeRing` (the last 24 h as sectors around a baseline); `timeline` (a day per entity as concentric rings, the detail of lights, plugs, thermostats and sensors); `colorWheel` + `wheelControls`; `keypad` (a phone's keypad over the object, for an `Action` that `asks` for a code: the board sends it again with `code`; `asks: 'words'` is an input in the open for what the viewer has to say, a question to the home, with the action's `hint` as its prompt, focused as it opens); a reading's `bearing` (degrees clockwise from the top) is an arrow on any ring: a heading, where the wind comes from; `swarmRing` (`radial/swarm.ts`) draws switches past `SWARM_FROM` (12) members as one SVG with a tick per member, the failing painted, a fleet or a hundred sensors; a reading's `plots` (bearing, range, label) are a radar behind the face (`radial/radar.ts`): things around a point; a plot with a `course` is a mark turned that way with its `vector` ahead (a ship, a drone), and the reading's `radar` names the rings and gives the center its own course; a reading's `globe` (`radial/globe.ts`: a center and plots by latitude and longitude) is the disc as the Earth, orthographic, with Natural Earth's 1:110m coasts (`radial/land.ts`, public domain, generated by `scripts/land.mjs` from the world-atlas package, not edited by hand) and a graticule; a reading's `map` (`radial/map.ts`: a center, a zoom, plots, a `{z}/{x}/{y}` tile template) is the disc as a window on a flat tiled map, OpenStreetMap's tiles by default with their credit at the bottom (their policy asks for light use; a product points `tiles` at its own server). The face takes one of them: map over globe over radar; in a detail the map is big, zoomable and draggable (a way back to the center once moved), the globe or the radar big, beside the reading's `list` where there is room (a row pointed at lights its dot). A reading's `list` is `scrollList` with `rows` (`radial/scroll.ts`): rows in the disc, a name and a line under it (`Seg.detail`, or what the label says after its first " · "), the dot of its level on a row that calls (`Seg.level`, or the alert's `fail` when the list is the ring's segments), off dim except in a choice, where the one chosen has a check; the changes view keeps the other shape, the items along the ring. An `Alert.key` names what the alert is about, so a value that drifts in its words is still the same alert (seen stays seen). The gear filters the groups by name past 24 members. A primitive enters the core when at least two domains share it or it is radial by nature; the rest is left to HA's more-info. Own components, not Orbit Kit's: the Kit injects styles in `document.head`, which the card's shadow root does not see. Sources may add `stream(entity)`, `history(entity, hours)` (hourly means) and `changes(entities, hours)` (state changes, for the timeline). A disc opens a detail only when the detail adds something the face does not have (a day of changes, a history, a long list, a picture, color, the month, several things to name); a control of one thing resolved on the face has no detail (`detailAdds` in `board/draw.ts`, `face` without `to`).
- Everything in this repo is in English: code, comments, identifiers, commits, docs and the demo's UI strings (core strings in `src/i18n.ts`, each app's in its `strings.ts`; another language is another dictionary). Chat with Martin stays in Spanish; the notes in `../coordinacion/` stay in Spanish.
- If a workaround shows up for something that belongs to Orbit or Zumly: do not leave it hidden in Pulse. Note it in `../coordinacion/PENDIENTES.md` under that project.
- Orbit (`@zumer/orbit` 2.2.0) and Zumly (1.2.2) come from npm, installed at the workspace root. To try an unpublished branch, it goes in as a `.tgz` in `vendor/` at the repo root: `../coordinacion/README.md`.
- Checks, from the root: `npm test` (lint, types, `compile`, then Playwright over the demo on 5173: `radial.spec.ts` and `phone.spec.ts`; the products' suites live in their repos, each over its recordings); `npm run dev` (5173; the component gallery at `/elements.html`); after changing a dependency version add `-- --force`. After changing the core, run the products' checks too (`npm test` in `../pulse-home` at least): they test what the core draws. Release like snapdom: commit subjects in Conventional Commits form, in English (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`; `!` after the type or a `BREAKING CHANGE` note for a breaking one): `npm run bump` (`@zumerbox/bump` suggests the version from them and tags it, `@zumerbox/changelog` writes `CHANGELOG.md`), `npm run release` (commits the changelog, pushes with the tag), `npm publish` (compiles first, `prepack`). Martin runs the publish.
