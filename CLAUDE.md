# Pulse

The UI: a radial object with layers by urgency. Uses Orbit (`../orbit`) and Zumly (`../zumly`). Pulse is more than Home Assistant; Home Assistant is the first real source and a thorough demonstration of it.

- npm workspace: `packages/core` (`@zumer/pulse`, the object and the board; knows nothing about Home Assistant or machines), `apps/demo` (simulated data on its own early board; the tests run against it), `apps/home-assistant` (the product over a live HA: `model.ts`, `source.ts` with the `PulseSource` interface and its WebSocket implementation, `host.ts` binding them to the core's `PulseHost`, sign-in, four board views; `model.ts` also builds the rooms, `roomSystems`: on the `axis: 'rooms'` the board's objects are the registry's areas, each with the systems' channels read within it), `apps/homelab` (a machine: `collector/collector.mjs` runs on it, `source.ts` reads the collector, `model.ts` the systems of a machine, `host.ts` the binding; `?demo` is a MacBook that is not there). Apps import the core as `@zumer/pulse`, never by relative path. What is UI of the object goes in the core; what is about a data source goes in its app.
- The contract (`packages/core/src/model.ts`): a `PulseHost` hands the board `systems` whose channels `read(ctx)` into a `Reading` (kind, value, big/label, `alert` with a level, `ids` of the things it depends on, optional dial/range/color/image/history/tracks); every thing is an opaque id the host names (`nameOf`, `stateOf`, `changedAt`, `unitOf`), every action an `Action` with the `ids` it touches that the host runs (`act`). The board (`board.ts`, `mountBoard`) owns the grid/orbit/layers/list views, the gear (four tabs: content, board, look, tuning), time in the orbit, the system view, the detail and the changes view; a shell passes `strings` for its own words. A host may add `groups()` (the gear filters by them), `byGroup()` (the board's second axis: one object per group), `statistics(id, days)` (the month of a meter), `language` and `stateText`. Hosts swapped at runtime (`setHost`) share system ids.
- The core's primitives (`radial.ts`): `ring` with `kind` `'p'` (band/dial, with `range` two knobs), `'s'` (switches), `'c'` (a choice, names along the ring); `face` with `image`; `timeRing` (the last 24 h as sectors around a baseline); `timeline` (a day per entity as concentric rings, the detail of lights, plugs, thermostats and sensors); `colorWheel` + `wheelControls`. A primitive enters the core when at least two domains share it or it is radial by nature; the rest is left to HA's more-info. Own components, not Orbit Kit's: the Kit injects styles in `document.head`, which the card's shadow root does not see. Sources may add `stream(entity)`, `history(entity, hours)` (hourly means) and `changes(entities, hours)` (state changes, for the timeline). A disc opens a detail only when the detail adds something the face does not have (a day of changes, a history, a long list, a picture, color, the month, several things to name); a control of one thing resolved on the face has no detail (`detailAdds` in `board.ts`, `face` without `to`).
- Everything in this repo is in English: code, comments, identifiers, commits, docs and the demo's UI strings (core strings in `packages/core/src/i18n.ts`, each app's in its `strings.ts`; another language is another dictionary). Chat with Martin stays in Spanish; the notes in `../coordinacion/` stay in Spanish.
- If a workaround shows up for something that belongs to Orbit or Zumly: do not leave it hidden in Pulse. Note it in `../coordinacion/PENDIENTES.md` under that project.
- Orbit (`@zumer/orbit` 2.2.0) and Zumly (1.2.2) come from npm, installed at the workspace root. To try an unpublished branch, it goes in as a `.tgz` in `vendor/` at the repo root: `../coordinacion/README.md`.
- Test Home Assistant: local Docker at `127.0.0.1:8123`. The app signs in with Home Assistant's own OAuth flow in the browser (Martin signs in; never type his credentials). For an automated live check, `apps/home-assistant/.env.local` (gitignored, not read by the app) still has `HA_URL/HA_USERNAME/HA_PASSWORD`: a script can run HA's login flow with them and seed `localStorage['pulse-ha-auth']` with the tokens.
- Integration options with Home Assistant (card, strategies, App, standalone) and the plan: `docs/home-assistant-integration.md`.
- `apps/home-assistant/card/`: the `pulse-card` custom card and the `pulse` dashboard and section strategies (one module, `npm run build:card`); `card/README.md` is the install/options guide for HA users (keep it current when the card changes). `app.ts` is the object mounted on an element (`mountPulse`, options `systems/areas/mode/start/settings`; the gear on the board lets the viewer choose within them, plus the channels of each system and the entity a channel follows, kept in `localStorage`); `main.ts` is the standalone shell; `card.html` is the card's bench over a demo home, no HA needed (what the tests use). To check the card in the local HA: `npm run dev:ha`, then `scripts/ha-tokens.mjs` + `scripts/ha-install-card.mjs` register the dev server's `dist-card/pulse-card.js` (new `?v=` each time) as a resource and the `pulse-demo` / `pulse-sections` dashboards; HA's own frontend can be opened in Playwright by seeding `localStorage['hassTokens']` with those tokens (again: never type credentials); `scripts/ha-check-card.mjs <tokens.json> <out dir>` does that for both dashboards and the editor, with screenshots.
- `apps/home-assistant/demo/`: the six homes of demo.home-assistant.io as a `PulseSource` (data and entity behaviour ported from `home-assistant/frontend`, Apache 2.0, `demo/NOTICE.md`). Regenerate the data with `demo/scripts/import-homes.py <frontend checkout>` (`--check` compares) rather than editing it by hand.
- Checks, from the root: `npm run typecheck`, `npm run lint`, `npm test` (Playwright starts the three apps: demo on 5173, HA on 5174, homelab on 5175; the HA app is tested over its demo homes, `?demo=home`, no HA needed; the homelab app over its demo machine, `?demo`, no collector needed; `PULSE_HA_TOKENS=<tokens.json> npx playwright test tests/ha-live.spec.ts` adds one run against the live HA). `npm run dev` / `npm run dev:ha` / `npm run dev:homelab`, `npm run collect` for the collector; after changing a dependency version add `-- --force`. The HA camera test loads an image from brands.home-assistant.io: it fails where that host is blocked.
