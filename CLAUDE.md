# Pulse

The UI: a radial object with layers by urgency. Uses Orbit (`../orbit`) and Zumly (`../zumly`). Pulse is more than Home Assistant; Home Assistant is the first real source and a thorough demonstration of it.

- npm workspace: `packages/core` (`@zumer/pulse`, the object and the board; knows nothing about Home Assistant or machines), `apps/demo` (simulated data on its own early board; the tests run against it), `apps/home-assistant` (the product over a live HA: `model.ts`, `source.ts` with the `PulseSource` interface and its WebSocket implementation, `host.ts` binding them to the core's `PulseHost`, sign-in, four board views; `model.ts` also builds the rooms, `roomSystems`: on the `axis: 'rooms'` the board's objects are the registry's areas, each with the systems' channels read within it), `apps/homelab` (a machine: `collector/collector.mjs` runs on it, `source.ts` reads the collector, `model.ts` the systems of a machine, `host.ts` the binding; `?demo` is a MacBook that is not there), `apps/world` (the world outside from public feeds, no server: `feeds.ts` is each feed as a URL and a parser into things, `source.ts` polls them on their own clocks, `model.ts` the sun, the earth, the sky over a place and the status pages; `?demo` runs the same parsers over recorded answers in `demo/data.ts`), `apps/signalk` (a boat: `source.ts` reads a Signal K server, the tree over REST then the WebSocket deltas, PUT for the autopilot; `model.ts` the systems of a vessel from its paths, SI in and a skipper's units out, the server's notifications as alerts; `?demo` is a yacht that is not there), `apps/fleet` (a fleet: `source.ts` listens to HSL's public MQTT feed over WebSocket with its own small client in `mqtt.ts`, gathering changes once a second; `model.ts` the fleet by dimension on the systems axis, each vehicle a tick on a swarm ring, and one object per vehicle on the groups axis, the lines as the gear's groups; `?demo` is 84 trams that are not there), `apps/prometheus` (a fleet of hosts: `config.ts` is the fleet as configuration, a PromQL query with thresholds per channel, node_exporter by default, `?config=` a JSON of the same shape; `source.ts` queries Prometheus on one clock and Alertmanager's alerts, posting silences; `model.ts` builds the systems from the configuration on both axes, each channel a swarm of hosts or a host's band; `?demo` is 24 hosts that are not there), `apps/drones` (a swarm: `source.ts` reads mavlink2rest's WebSocket stream of MAVLink as JSON, one drone per system id, and posts COMMAND_LONG for arm, takeoff and mode; `model.ts` the swarm by dimension with a radar around home and one object per drone whose mode is a choice ring; an alert's acts are one command per drone, "bring them home"; `?demo` is six copters that are not there), `apps/flights` (the sky: `source.ts` asks a community ADS-B network, adsb.lol by default, for the emergency squawks anywhere and the aircraft around a place, and OpenSky for the whole sky now and then, each on its own clock; `model.ts` the emergencies on the globe, the region as a radar with arrivals, departures and holds, the anomalies the stream alone can tell (a fast descent, a lost signal, low and slow far from an airport), the sky binned on the globe, and one object per aircraft on the groups axis; `?demo` is a recorded sky), `apps/iss` (the space station: `lightstreamer.ts` is its own small client of Lightstreamer's protocol (TLCP over WebSocket) for NASA's public ISS telemetry, `telemetry.ts` the PUIs it reads with their names, units and states; `feeds.ts` the position from wheretheiss.at and the station, crew and launches from Launch Library 2, whose answers `source.ts` keeps in `localStorage` (fifteen questions an hour); `model.ts` one object per discipline, air, water, power, thermal, attitude, station, orbit, links, launches, with thresholds of its own, and a launch as an object; `?demo` is ten recorded seconds, `demo/recording.json` from `demo/scripts/record.mjs`, through the same decoder). Apps import the core as `@zumer/pulse`, never by relative path. What is UI of the object goes in the core; what is about a data source goes in its app.
- The contract (`packages/core/src/model.ts`): a `PulseHost` hands the board `systems` whose channels `read(ctx)` into a `Reading` (kind, value, big/label, `alert` with a level, `ids` of the things it depends on, optional dial/range/color/image/history/tracks); every thing is an opaque id the host names (`nameOf`, `stateOf`, `changedAt`, `unitOf`), every action an `Action` with the `ids` it touches that the host runs (`act`). The board (`board/`, `mountBoard` in `board/mount.ts`) owns the grid/orbit/layers/list views, the gear (four tabs: content, board, look, tuning), time in the orbit, the system view, the detail and the changes view; a shell passes `strings` for its own words. A host may add `groups()` (the gear filters by them), `byGroup()` (the board's second axis: one object per group), `objectOf(id)` (the object of one thing a segment or a row names with `Seg.to`: the board zooms into it from there and reads it while it is open; an aircraft, a quake), `statistics(id, days)` (the month of a meter), `language` and `stateText`. A reading's `map` opens a detail with the map big, live and zoomable (`mapDetail`/`turnMap`/`mapControls` in `radial/map.ts`; it keeps the pinch, `data-zooms`); its `link` is a way out to the thing elsewhere, a button in the detail. Hosts swapped at runtime (`setHost`) share system ids.
- Inside `board/`: `context.ts` is the `Board` one mounted board shares (fixed parts, the host and the viewer's choices, readings and actions, caches); every module is functions of it. `types.ts` (public shapes), `settings.ts` (frame, choices, look, ground), `state.ts` (readings, order, actions, the code), `draw.ts` (ring with pending/failed, pictures, `setHTML`), `time.ts` (past changes, the month), `dials.ts`, `gear.ts`, `views/` (system, detail, changes, and `board/` with a file per mode: grid, orbit, layers, list, around `index.ts`), `mount.ts` (makes the `Board`, wires host and Zumly). The stylesheet is `style.css` importing `styles/` (base, object, detail, phone, primitives, board, orbit, layers, gear, compact, list, time, ground) in the order they cascade: a rule moved between parts can change what wins. The lower modules call up through two hooks on the `Board` (`repaint`, `systemView`), never by importing `mount.ts` or a view: no import cycles. A field that changes (`b.host`, `b.local`, `b.ids`, `b.readings`) is read through `b` each time, never kept in a local.
- The core's primitives (`radial/`, a module per family, each primitive next to its gestures; `radial/index.ts` re-exports them): `ring` with `kind` `'p'` (band/dial, with `range` two knobs), `'s'` (switches), `'c'` (a choice, names along the ring); `face` with `image`; `timeRing` (the last 24 h as sectors around a baseline); `timeline` (a day per entity as concentric rings, the detail of lights, plugs, thermostats and sensors); `colorWheel` + `wheelControls`; `keypad` (a phone's keypad over the object, for an `Action` that `asks` for a code: the board sends it again with `code`); a reading's `bearing` (degrees clockwise from the top) is an arrow on any ring: a heading, where the wind comes from; `swarmRing` (`radial/swarm.ts`) draws switches past `SWARM_FROM` (12) members as one SVG with a tick per member, the failing painted, a fleet or a hundred sensors; a reading's `plots` (bearing, range, label) are a radar behind the face (`radial/radar.ts`): things around a point; a reading's `globe` (`radial/globe.ts`: a center and plots by latitude and longitude) is the disc as the Earth, orthographic, with Natural Earth's 1:110m coasts (`radial/land.ts`, public domain, generated by `packages/core/scripts/land.mjs` from the world-atlas package, not edited by hand) and a graticule; a reading's `map` (`radial/map.ts`: a center, a zoom, plots, a `{z}/{x}/{y}` tile template) is the disc as a window on a flat tiled map, OpenStreetMap's tiles by default with their credit at the bottom (their policy asks for light use; a product points `tiles` at its own server). The face takes one of them: map over globe over radar. An `Alert.key` names what the alert is about, so a value that drifts in its words is still the same alert (seen stays seen). The gear filters the groups by name past 24 members. A primitive enters the core when at least two domains share it or it is radial by nature; the rest is left to HA's more-info. Own components, not Orbit Kit's: the Kit injects styles in `document.head`, which the card's shadow root does not see. Sources may add `stream(entity)`, `history(entity, hours)` (hourly means) and `changes(entities, hours)` (state changes, for the timeline). A disc opens a detail only when the detail adds something the face does not have (a day of changes, a history, a long list, a picture, color, the month, several things to name); a control of one thing resolved on the face has no detail (`detailAdds` in `board/draw.ts`, `face` without `to`).
- Everything in this repo is in English: code, comments, identifiers, commits, docs and the demo's UI strings (core strings in `packages/core/src/i18n.ts`, each app's in its `strings.ts`; another language is another dictionary). Chat with Martin stays in Spanish; the notes in `../coordinacion/` stay in Spanish.
- If a workaround shows up for something that belongs to Orbit or Zumly: do not leave it hidden in Pulse. Note it in `../coordinacion/PENDIENTES.md` under that project.
- Orbit (`@zumer/orbit` 2.2.0) and Zumly (1.2.2) come from npm, installed at the workspace root. To try an unpublished branch, it goes in as a `.tgz` in `vendor/` at the repo root: `../coordinacion/README.md`.
- Test Home Assistant: local Docker at `127.0.0.1:8123`. The app signs in with Home Assistant's own OAuth flow in the browser (Martin signs in; never type his credentials). For an automated live check, `apps/home-assistant/.env.local` (gitignored, not read by the app) still has `HA_URL/HA_USERNAME/HA_PASSWORD`: a script can run HA's login flow with them and seed `localStorage['pulse-ha-auth']` with the tokens.
- Integration options with Home Assistant (card, strategies, App, standalone) and the plan: `docs/home-assistant-integration.md`.
- `apps/home-assistant/card/`: the `zumer-pulse` custom card and the `zumer-pulse` dashboard and section strategies (one module, `npm run build:card`; the Zumer prefix because other HA cards already use "pulse"); `card/README.md` is the install/options guide for HA users (keep it current when the card changes). `app.ts` is the object mounted on an element (`mountPulse`, options `systems/areas/mode/start/settings`; the gear on the board lets the viewer choose within them, plus the channels of each system and the entity a channel follows, kept in `localStorage`); `main.ts` is the standalone shell; `card.html` is the card's bench over a demo home, no HA needed (what the tests use). To check the card in the local HA: `npm run dev:ha`, then `scripts/ha-tokens.mjs` + `scripts/ha-install-card.mjs` register the dev server's `dist-card/zumer-pulse.js` (new `?v=` each time) as a resource and the `pulse-demo` / `pulse-sections` dashboards; HA's own frontend can be opened in Playwright by seeding `localStorage['hassTokens']` with those tokens (again: never type credentials); `scripts/ha-check-card.mjs <tokens.json> <out dir>` does that for both dashboards and the editor, with screenshots.
- `apps/home-assistant/demo/`: the six homes of demo.home-assistant.io as a `PulseSource` (data and entity behaviour ported from `home-assistant/frontend`, Apache 2.0, `demo/NOTICE.md`). Regenerate the data with `demo/scripts/import-homes.py <frontend checkout>` (`--check` compares) rather than editing it by hand.
- Checks, from the root: `npm run typecheck`, `npm run lint`, `npm test` (Playwright starts the ten apps: demo on 5173, HA on 5174, homelab on 5175, world on 5176, Signal K on 5177, fleet on 5178, Prometheus on 5179, drones on 5181 (5180 is the homelab collector), flights on 5182, ISS on 5183; the HA app is tested over its demo homes, `?demo=home`, no HA needed; the homelab app over its demo machine, `?demo`, no collector needed; the world app over its recorded day, the Signal K app over its recorded yacht the fleet app over its recorded trams, the Prometheus app over its recorded hosts, the drones app over its recorded swarm, the flights app over its recorded sky and the ISS app over its recorded pass, `?demo`, no feeds, server, broker or simulator needed; `PULSE_HA_TOKENS=<tokens.json> npx playwright test tests/ha-live.spec.ts` adds one run against the live HA). `npm run dev` / `npm run dev:ha` / `npm run dev:homelab` / `npm run dev:world` / `npm run dev:signalk` / `npm run dev:fleet` / `npm run dev:prometheus` / `npm run dev:drones` / `npm run dev:flights` / `npm run dev:iss`, `npm run collect` for the collector; after changing a dependency version add `-- --force`. The HA camera test loads an image from brands.home-assistant.io: it fails where that host is blocked.
